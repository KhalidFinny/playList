# M3 Expressive Token Spec — PlayList

The design source of truth for this migration. Every value here is either taken from the M3
spec or generated by the real M3 algorithm (`@material/material-color-utilities`). Nothing here
is eyeballed.

---

## 1. Direction

### The reference screenshot

Khalid supplied the m3.material.io **M3 Expressive** landing page. Described as the spec:

- **Surfaces** — very light warm neutral page background; content sits on large-radius cards
  with **no border**, separated by tonal surface difference rather than strokes. Card radius is
  roughly **28px** (M3 `extra-large`).
- **Grid** — a 2-card row above a 3-card row. Cards are equal height within a row, generous
  internal padding (~28–32px), and a consistent gutter (~16–20px).
- **Palette in the card artwork** — deep purple `#4A1A5C`, bright purple `#9C27B0`, lavender
  `#C9A7EB`, pink `#FFB4AB`, charcoal `#1E1E1E`. This is Google's own expressive sample art,
  **not** a palette instruction — PlayList's palette is seeded from orange instead.
- **Typography** — Google Sans Flex throughout. Card titles ~22–24px at medium weight, body
  ~14–15px regular, body color a mid gray. The "Oh, hi! I'm Google Sans Flex!" card mixes
  filled and outlined weights of the same family at display size.
- **Shape** — pill buttons (`Pause`), large-radius rectangles, circles, and decorative shapes:
  flowers, blobs, cookies, squiggles. Pink/purple/lavender on dark purple.
- **Motion physics card** — dark charcoal panel with vertical bar sequences, i.e. waveform
  bars, in lavender on gray blocks.
- **Icons** — outlined, ~2px stroke, rounded caps and joins.

### Decisions

| Decision | Value |
| --- | --- |
| Approach | M3 mechanics **and** M3 Expressive look, hand-built on Tailwind v4 + radix/`cva` |
| Component library | **None.** MUI is MD2; `@material/web` is in maintenance mode |
| Seed | orange, `#f97316` (HCT H 46.4 / C 70.0 / T 63.7) |
| Scheme | **Light first.** Dark tokens defined, not activated |
| Typeface | **Google Sans Flex** (OFL-1.1), fallback Roboto → Noto Sans |
| Shape scale | Uncapped, up to `full`; assigned **per component role**, not uniformly |
| Type floor | 12px, hard |
| Motion | M3 Expressive springs |

## 2. Color

### 2.1 Why the brand orange cannot be the primary

The M3 algorithm maps a seed to tone **40** for light `primary`. Seeding with `#f97316` yields
**`#9d4300`** — a deep burnt orange, not the brand orange. The brand orange sits at tone ~64.

This is not a bug to work around; it is the system. The consequence is deliberate:

| Role | Tone | Hex | vs white text |
| --- | --- | --- | --- |
| M3 spec `primary` | 40 | `#9d4300` | 6.49:1 pass |
| **Chosen `primary`** | **45** | **`#b14c00`** | **5.38:1 pass** |
| | 50 | `#c45600` | 4.49:1 large only |
| | 60 | `#ec6a06` | 3.17:1 fail |

**Decision: light `primary` = tone 45 (`#b14c00`).** Tone 40 is spec-exact but reads brown.
Tone 45 is the most vivid tone that still passes AA with a white label. Tone 50 and above are
not usable for a filled button with white text.

The vivid orange survives where it is safe:

- On the landing hero's `#050505` backdrop, `#f97316` measures **7.27:1** — pass. The hero keeps it.
- As `primary-container` / accent surfaces at tone 90 (`#ffdbca`) with `on-primary-container`
  at tone 10, which measures **13.24:1**.

## 3. Typography

**Family:** Google Sans Flex — OFL-1.1, open-sourced Nov 2025, on Google Fonts.
Variable axes: `wght` 1–1000, `wdth` 25–151, `slnt` −10–0, `opsz` 6–144, `GRAD` 0–100,
`ROND` 0–100.

Chosen over Roboto because it is the typeface M3 Expressive is designed around, and because its
`ROND` axis pairs with the shape system — Google's own shape docs state M3 shapes and Google
Sans Flex share roundness attributes. Fallback chain per Google: Google Sans Flex → Roboto →
Noto Sans.

### Type scale

| Token | Size | Line | Weight | Tracking |
| --- | --- | --- | --- | --- |
| display-large | 57 | 64 | 400 | −0.25 |
| display-medium | 45 | 52 | 400 | 0 |

| headline-medium | 28 | 36 | 400 | 0 |
| headline-small | 24 | 32 | 400 | 0 |

| title-medium | 16 | 24 | 500 | 0.15 |
| title-small | 14 | 20 | 500 | 0.1 |
| body-large | 16 | 24 | 400 | 0.5 |
| body-medium | 14 | 20 | 400 | 0.25 |
| body-small | 12 | 16 | 400 | 0.4 |
| label-large | 14 | 20 | 500 | 0.1 |
| label-medium | 12 | 16 | 500 | 0.5 |

`label-small` is **11px** in the M3 baseline scale. Raised to 12px to satisfy the project's hard
12px floor. This is the only scale deviation.

**Emphasized** variants (M3 Expressive) raise weight to 600–700 at the same size and are used
for hero moments and editorial treatment.

## 4. Shape

### Corner radius scale (uncapped, per Khalid's call)

```txt
none                     0
extra-small              4px
small                    8px
medium                   12px
large                    16px
large-increased          20px
extra-large              28px
extra-large-increased    32px
extra-extra-large        48px
full                     9999px
```

### Assignment by component role

Shape **contrast** is the system — M3 Expressive pairs sharp and round deliberately. Radius is
therefore assigned per role, not applied uniformly.

| Component | Radius |
| --- | --- |
| Button, icon button, segmented button, chip | `full` |
| FAB | `large` (16) |
| Card | `medium` (12) |
| Dialog | `extra-large` (28) |
| Bottom sheet | `extra-large` (28) top |
| Menu, tooltip, snackbar | `extra-small` (4) |
| Text field (filled) | `extra-small` (4) top, 0 bottom |
| Text field (outlined) | `extra-small` (4) |
| Navigation rail active indicator | `full` |
| Switch, slider handle | `full` |

### The 5 shape-library shapes

Selected from the 35-shape M3 Expressive library for music/vinyl resonance, each bound to a
real UI role rather than used as decoration.

| # | M3 shape | Why it fits music | UI role |
| --- | --- | --- | --- |
| 1 | **`Cookie12Sided`** | A 12-sided scalloped disc reads as a **vinyl record** — the app's whole identity | Album-art masks, now-playing disc, participant avatars |
| 2 | **`Burst`** | A **beat / needle drop** — the moment sound starts | Play button, FAB, "now playing" pulse |
| 3 | **`Flower`** | A **sound bloom** — audio radiating outward | Equalizer / visualizer accents, empty states |
| 4 | **`Puffy`** | A **soft waveform blob** — warm, analog, non-jagged | Ambient background blobs, chips, hero backing |
| 5 | **`Fan`** | **Sound dispersion** from a speaker cone | Station cards, section accents |

Exact M3 identifiers for reference: `Cookie12Sided`, `Burst`, `Flower`, `Puffy`, `Fan`.
Other available shapes if a swap is wanted: `Cookie4Sided`, `Cookie6Sided`, `Cookie7Sided`,
`Cookie9Sided`, `Clover4Leaf`, `Clover8Leaf`, `SoftBurst`, `Boom`, `SoftBoom`, `Sunny`,
`VerySunny`, `Ghostish`, `PixelCircle`, `PixelTriangle`, `PuffyDiamond`, `Bun`, `Gem`,
`ClamShell`, `Arch`, `Slanted`, `Heart`, `Pentagon`, `SemiCircle`, `Oval`, `Pill`, `Diamond`,
`Triangle`, `Square`, `Circle`, `Arrow`.

### Loading indicator (the squiggle)

The M3 Expressive **loading indicator**: a shape that morphs continuously between library
shapes, driven by the expressive spring. Google's default morph is
`Cookie9Sided → Pentagon → SoftBurst`.

**PlayList's morph: `Cookie12Sided → Burst → Flower`** — the same mechanism, music-flavoured.
Replaces the current `LoadingOverlay` spinner and `SoundwaveVisualizer` idle state.

> Web status: M3 lists the loading indicator and shape morph as **"Web: Unavailable"**. This is
> hand-authored: SVG paths interpolated per-frame, or `<path d>` morphing.

## 5. Motion

Spring tokens confirmed against `androidx.compose.material3.tokens.ExpressiveMotionTokens`
and the M3 spec's spring→curve conversion table.

### Expressive scheme (chosen)

| Token | Damping | Stiffness |
| --- | --- | --- |
| fast.spatial | 0.6 | 800 |
| default.spatial | 0.8 | 380 |
| slow.spatial | 0.8 | 200 |
| fast.effects | 1.0 | 3800 |
| default.effects | 1.0 | 1600 |
| slow.effects | 1.0 | 800 |

### Standard scheme (for utilitarian moments)

| Token | Damping | Stiffness |
| --- | --- | --- |
| fast.spatial | 0.9 | 1400 |
| default.spatial | 0.9 | 700 |
| slow.spatial | 0.9 | 300 |
| fast/default/slow.effects | 1.0 | 3800 / 1600 / 800 |

### Web conversion (CSS)

Web cannot run Compose springs. Google's guidance: use springs where the animation can be
interrupted or driven by gesture, otherwise use the curves that mimic them.

| Spring | Cubic bezier | Duration |
| --- | --- | --- |
| expressive fast spatial | `0.42, 1.67, 0.21, 0.90` | 350ms |
| expressive default spatial | `0.38, 1.21, 0.22, 1.00` | 500ms |
| expressive slow spatial | `0.39, 1.29, 0.35, 0.98` | 650ms |
| expressive fast effects | `0.31, 0.94, 0.34, 1.00` | 150ms |
| expressive default effects | `0.34, 0.80, 0.34, 1.00` | 200ms |
| expressive slow effects | `0.34, 0.88, 0.34, 1.00` | 300ms |
| standard fast spatial | `0.27, 1.06, 0.18, 1.00` | 350ms |
| standard default spatial | `0.27, 1.06, 0.18, 1.00` | 500ms |
| standard slow spatial | `0.27, 1.06, 0.18, 1.00` | 750ms |
| standard fast/default/slow effects | `0.31, 0.94, 0.34, 1.00` / `0.34, 0.80, 0.34, 1.00` / `0.34, 0.88, 0.34, 1.00` | 150/200/300ms |

Framer Motion uses the spring form directly (`stiffness`, `damping`); CSS uses the curves.

Applied as an overlay of `currentColor` at these opacities:

### Elevation

M3 expresses elevation as **surface tint + level**, not heavy shadow. Levels 0, 1, 3, 6, 8, 12.
Shadows stay light and functional (overlays, focus) per the project's UI rules.
